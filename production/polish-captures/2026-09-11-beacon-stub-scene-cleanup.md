## The final-game picture this serves

A year from now the Haven-screen slice adds **one roster line and one prefab**
and touches nothing else. Today the project carries four stub scenes that
present nothing, a roster entry pointing at one of them, four build-settings
entries, and an authoring path that silently recreates all of it on every
`Author All Scenes`. The 1.0 shape is: a beacon type without a binding entry has
no presentation *by design*.

## Commit order is load-bearing

`AuthorBeaconStubScene` calls `EnsureSceneInBuildSettings`, which only ever ADDS.
Commit A (remove the caller) must land before Commit B (delete the files), or
the next author run recreates scene *and* build entry.

Regenerate the SO with **`Author Beacon Scene Binding` only** — `Author All
Scenes` re-authors `ChopshopRoot.prefab` and reissues its fileIDs, dragging
churn into Commit A and risking the documented chopshop-boots-over-the-map state.

  validation warning on every new SO plus a re-audit of 11 test construction
  sites.
- **A3 (roster-shape EditMode test) is non-optional.** The SO's contract
  silently weakens from "every non-Start type is bound" to "bound types are
  bound", and nothing else enforces the weaker form.
- **A2 (grep gate on `AuthorBeaconStubScene`) is the resurrection immunity** —
  without it, immunity depends on commit order holding forever.

**Test blast radius: nothing can red.** Zero references to

(`ChopshopBeaconRevisit_Test:155-158`, `ChopshopRepairMode_Test:641-644`) and
